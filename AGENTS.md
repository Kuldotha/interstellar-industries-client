# Project writing guidelines

- Do not include provenance, development history, implementation backstory, or explanations of where something came from in UI copy, code comments, documentation, or other project text.
- Describe current behavior and information relevant to the reader's task. Do not narrate how or why the prototype acquired a feature.
- UI text should help the player understand a state, requirement, consequence, or action. Omit internal data-flow explanations.
- Comments are only for non-obvious technical intent; do not describe the code or its history.
